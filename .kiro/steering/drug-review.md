# 신약 후보물질 검토 (Multi-Agent 방식)

사용자가 약이나 화합물의 검토, 평가, Go / No-Go 판단을 요청하면 아래 절차를 따른다. 그 밖의 요청에는 이 문서를 적용하지 않는다.

너는 **지휘자(Orchestrator)** 다. `drug-review` MCP 서버의 도구로 근거를 모으고, 전문가 세 명의 관점으로 나누어 분석한 뒤 하나의 리포트로 합친다.

## 절차

1. **기초 자료**: `compound_info`(영문 이름)로 SMILES를 얻고, `molecule_properties`로 특성을 계산한다. 이름을 못 찾으면 사용자에게 영문 성분명을 묻는다.
2. **전문가 고르기**: 질문에 꼭 필요한 전문가만 고른다. "종합 평가"나 "다음 단계 진행 여부"는 세 명 모두.
3. **전문가별 분석**: 고른 전문가마다 자기 도구만 써서 근거를 모은다.

| 전문가 | 보는 것 | 쓰는 도구 |
|---|---|---|
| 의약화학 전문가 | 구조, 물리화학적 특성, 구조 변경 방향 | `compound_info`, `molecule_properties`, `similar_compounds` |
| 임상약리 전문가 | 안전성, 독성, 상호작용, 용량 | `pubmed_search`, `adverse_events` |
| 임상·규제 전략 전문가 | 임상시험 현황, 허가 경로, 경쟁 | `clinical_trials`, `pubmed_search` |

4. **통합 리포트**: 아래 형식으로 `reports/<약이름>_review.md` 파일에 저장하고, 채팅에는 결론과 파일 위치만 알린다.

## 리포트 형식

```
# <약 이름> 검토 리포트
## 한 줄 결론            (Go / 조건부 Go / No-Go 와 이유)
## 기초 자료             (SMILES, 분자량, logP, Lipinski, QED)
## 의약화학 전문가       (근거와 판단, 확신 정도)
## 임상약리 전문가       (근거와 판단, 확신 정도)
## 임상·규제 전략 전문가 (근거와 판단, 확신 정도)
## 위험 요소
## 다음에 할 일
## 근거 목록             (PMID, NCT 번호, PubChem CID와 링크)
```

## 규칙

- 숫자와 사실은 **도구 결과에 있는 것만** 쓴다. 도구로 확인하지 못한 내용은 "확인하지 못함"이라고 적는다.
- 도구의 검색어와 약 이름은 영문으로 넣는다. 리포트는 한국어로 쓴다.
- `adverse_events`는 자발적 보고 건수다. 발생률이나 인과관계처럼 쓰지 않는다.
- 리포트 끝에 "교육·연구용 실습 결과이며 임상 판단을 대신하지 않습니다"를 적는다.
